# Public Beta Announcement for Developers

## Preamble: when, how, and why to use this version

Use this version when the product has moved beyond founder-guided private testing and is ready for wider developer evaluation.

### Use it when
- outside developers have already tested it successfully;
- at least a few have built or adapted modules;
- the extension model is no longer theoretical;
- docs answer the most obvious questions;
- install/setup is reasonably smooth;
- pricing and licensing can be explained clearly;
- you can support a wider wave of inbound interest.

### Do not use it when
- every new user still requires personal onboarding;
- the public API is still churning heavily;
- your docs are mostly incomplete notes;
- your marketplace story is still vague.

### Why this version exists
The goal is to broaden awareness, expand the ecosystem, and attract more builders without overselling maturity.

### How to distribute it
Best channels:
- public blog post;
- project website announcement;
- GitHub release/discussion;
- CMS forum/Discord/Slack/community channels;
- founder social posts;
- selected technical communities.

This version can be shared broadly, but it should still be framed as **beta**, not general availability.

The public beta includes:

## Licensing, clearly

The core is **source-available**, not open source.

That means:

- you can inspect the code;
- you can use it for development, testing, staging, and evaluation;
- **production commercial use requires a paid license**.

Third-party module authors are welcome. Marketplace-listed module authors will be able to use their own licensing model, including commercial licensing, while paid marketplace transactions run through the official marketplace.
